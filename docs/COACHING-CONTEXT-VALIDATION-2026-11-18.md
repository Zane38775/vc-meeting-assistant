# beta.5：会议上下文与资料整理恢复

日期：2026-11-18（北京时间）。候选版本 `0.1.2-beta.5`；公开 Release 仍为 v0.1.0，未合并 main。本轮按使用者要求继续无需讲话的开发，不开启采集或保存新原始音频。

## 环境与复现

Apple M1、16 GiB、macOS 27.0.1（26A434）；原生 arm64 Node.js 24.22.3 / npm 11.19.1，Electron 45.3.3。源码在非 iCloud 缓存目录工作，保留原 Documents 工作树。以下复现使用临时 SQLite、虚构文本和受控服务响应，没有改写使用者会议。

1. 会前已知有试点，会中较早明确回答尚未付费，对应问题标为已回答。继续输入超过 40 段，并使旧问题落到最近 30 题之外。旧实现发送的上下文中，两项都消失；改写同议题、换新引文仍可通过现有去重。不能要求模型使用从未收到的早期答案。
2. 技术检索成功保存来源，第一次中文整理抛错、返回空结果或超时。之后另一个问题再次关联相同检索词。旧实现一见缓存来源就返回，后续中文整理永远不再执行，页面只剩来源和失败状态。

## 修改

- 保留最近 40 段引用窗口，额外补入较早定稿原文和较早问题的原文/当前状态。发言按录音时间排序，排除缺口、临时字幕和已在近期窗口的重复项。不是额外生成的 AI 摘要，也不更改历史字幕或自动标记问题已回答。
- 较早原文最多 200 段、序列化 JSON 24,000 字符；较早问题最多 120 题、同样 24,000 字符。预算优先保留靠近当前的历史，巨型单项跳过，输入报告省略数量。历史用于核对已答、重复和前后矛盾；输出引用仍须通过原有本轮来源校验。
- 已有来源、整理缺失或失败时，后续同查询在 30 秒冷却后只重新整理缓存摘要；不会重复搜索。并发调用合并，成功资料卡直接复用，每次真实服务请求继续计入上限。即便整理失败，已有来源仍可立即关联和显示，字幕继续保存。
- 已完成失败的冷却时间可从 SQLite 恢复。明确请求超时、取消与过期结果边界；删除或关闭后的迟到响应不会复活资料，旧结果不会覆盖新的成功结果。

## 边界与待验证

- 历史上下文仍有上限，不是无限会议记忆。单轮新增超过 40 条时，溢出段仍在转写记录中，但不进入该轮分析，输入明确省略数；未因这次改动增加逐条分析请求。
- 已答/已忽略状态帮助模型判断，不保证所有换措辞的重复问题都被语义识别。BP 引文可核对原文也不等于相应推断已被独立证明。
- 资料整理重试由后续相同查询触发，没有后台定时重试。若进程在首次整理结果落盘前退出，重启后的查询可能再次发起整理请求；本次没有新增跨重启的调用额度账本。
- 资料仍基于检索摘要，未自动抓取和阅读全文。
- 英文及专名识别未在本次修改。仍默认 X-ASR，Qwen 对照结论见[模型记录](ASR-QWEN-EVALUATION-2026-11-18.md)。真人英文、专业追问、直接结束尾句、腾讯会议双向收音和基础流程通过后的 60 分钟测试仍待验收。
- 已知缺少自动说话人分离、扫描 BP OCR、异地共享服务，继续与故障分开记录。密钥、BP、用户数据库、原音和会话凭据不进入 Git。
